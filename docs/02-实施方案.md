数据源实测（2026-11-20，curl 直连）：

| 来源 | 端点 | 结果 | 条目内容 |
|---|---|---|---|
| Bloomberg | `https://www.bloomberg.com/feeds/markets/news.rss`（另测 politics / technology / economics） | 全部 200，约 15KB，20 条/频道 | title + **description（自带摘要）** + link + **pubDate（20/20）** ✅ |
| WSJ | `https://feeds.content.dowjones.io/public/rss/RSSMarketsMain`（另测 RSSWorldNews、RSSWSJD） | 全部 200，40~74 条/频道（实测实时更新） | title + **description（100%）** + link + **pubDate（100%）** ✅ |
| WSJ（旧域名） | `https://feeds.a.dj.com/rss/*.xml` | 返回 200 但**已停更于 2025-01-27**，弃用 | — |
| Reuters | `https://news.google.com/rss/search?q=site:reuters.com%20when:24h&hl=en-US&gl=US&ceid=US:en` | 200，100 条/次 | title 带「 - Reuters」后缀；link 为 news.google.com 跳转链接；**pubDate（100/100）** ✅；无 description |
| 旧域名 | `feeds.bloomberg.com/*` | 301 → `www.bloomberg.com/feeds/*`（配置直接用新域名） | — |
| GN 头条 | `https://news.google.com/rss?hl=en-US&gl=US&ceid=US:en`（Top Stories） | 200，38 条 | 含 `<source>` 媒体名标签，作为要闻判定信号源 |
| GN 商业 | `https://news.google.com/rss/topics/CAAqKggKIiRDQkFTRlFvSUwyMHZNRGx6TVdZU0JXVnVMVlZUR2dKVlV5Z0FQAQ?hl=en-US&gl=US&ceid=US:en`（Business，已用重定向后地址） | 200，67 条 | 同上，作为要闻判定信号源 |
| Reuters 直连 | `https://www.reuters.com/{,world,markets,business,technology}/feed/` | **全部 401**；robots.txt 明示「未经书面许可禁止自动化采集」 | **放弃直连**，维持 Google News RSS |

**关键结论**：
1. Bloomberg、WSJ 走官方 RSS 且自带摘要 → **无需抓取文章页面**；
2. Reuters 走 Google News RSS，无摘要 → 对部分条目回退抓取文章页 `og:description`（限速、可选、失败即空）；
3. Google News 跳转链接（`news.google.com/rss/articles/...`）为服务端重定向，**浏览器打开无障碍**，直接作为展示链接使用，不做服务端解析（2024 年后该跳转改为 base64 编码，curl 跟进不稳定，解析成本高）；Reuters 去重键改用 `reuters:` + 标题规范化哈希。

## 2. 系统架构与数据流

```
GitHub Actions cron 每小时（主）/ 本地调度器（可选，launchd / systemd / 任务计划）
   └─ python -m src.main run
        ├─ ① fetchers（3 个适配器并行抓取）
        │     bloomberg.py  ← 4 个官方 RSS
        │     wsj.py        ← 3 个官方 RSS
        │     reuters_gn.py ← Google News RSS（when:24h）
        ├─ ② 归一化 → Item（title/summary/link/published_at/source/feed_topic）
        │     reuters：剥离「 - Reuters」标题后缀
        ├─ ③ classifier：关键词分类（china > us > 频道映射/关键词 > world 兜底，英文词边界匹配）
        ├─ ④ dedup：查数据库（SQLite 主 / MySQL 可选：L1 URL guid + L2 source+标题哈希+归属日）
        ├─ ⑤ 新条目 INSERT articles（写入 published_at 与 created_at）
        ├─ ⑤+ fetch_meta：仅针对本批新入库且无摘要的 Reuters 条目抓 og:description（限速 ≤1/s，≤20 条/批）
        ├─ ⑥ translator：google gtx（默认）/ llm（可选）译新条目并回填 title_zh / summary_zh / translated
        ├─ ⑥+ importance：三信号打分（标题特征词 / 跨源相似度 / GN 头条命中），
        │     对本批受影响的近 3 天日期全量重算，回填 is_important / important_reason
        ├─ ⑦ archive：daily/ 中日期 <（今天 − 2 天）的文件移入 archive/（并以归档横幅重写避免失效相对链接）
        ├─ ⑧ render：原子重写最近 3 天 daily/*.html + 根 index.html（今日日报）+ archive/index.html
        ├─ ⑨ 写 fetch_batches + logs/YYYY-MM-DD.log
        └─ ⑩ 云端模式：同步 data/news.db + index.html + daily/ + archive/ + .nojekyll
              至 generated 分支，中文 commit 提交并 push → GitHub Pages 自动发布
```

## 3. 数据源接入设计

### 3.1 Bloomberg（官方 RSS）

| feed_topic | 初始类目 |
|---|---|
| markets / economics | markets |
| technology | tech |
| politics | world |

- 所有条目均依次过 `china` > `us` 关键词覆盖链，命中即覆盖初始频道类目；
- feedparser 解析，description（去除多余 HTML 标签后）直接作为 `summary_en`，`pubDate` 转 `Asia/Shanghai` ISO-8601 存为 `published_at`。

### 3.2 WSJ（官方 RSS）

| feed | 初始类目 |
|---|---|
| RSSMarketsMain | markets |
| RSSWSJD | tech |
| RSSWorldNews | world |

- link 自带 `?mod=rss_xxx` 跟踪参数 → URL 规范化时去除；
- description 直接作为 summary_en。

### 3.3 Reuters（Google News RSS）

- 查询：`site:reuters.com when:24h`（单次查询全量 100 条，主题分类交给关键词规则，不按主题多次查询以降低被限流概率）；
- 标题处理：正则剥离尾部「 - Reuters」；
- `url_display` = Google 跳转链接（浏览器可直接打开原文）；
- `guid` = `reuters:` + md5(规范化标题)；
- 摘要回退：无 description → 对该条目抓文章页 `og:description` / `<meta name="description">`（§3.4）；
- **直连放弃说明**（2026-11-20 实测）：reuters.com 官方 feed 全部 401，robots.txt 明示禁止自动化采集，故不采用直连；Google News RSS 为第三方公开索引，实测稳定。

### 3.4 og:description 回退（仅 reuters 条目）

- httpx GET 文章 URL，普通浏览器 UA，超时 5s；
- 限速 ≤1 次/秒，每批次最多 20 条（控制请求量）；
- 只解析 meta 标签，不解析正文；
- **失败定义与处理**：

| 类别 | 具体情形 | 处理 |
|---|---|---|
| 瞬态失败 | 网络超时、连接重置、HTTP 5xx、429 | 间隔 2s 重试 1 次 |
| 确定性失败 | 403/401（Akamai 拦截等）、404、返回 200 但解析不到 meta description、摘要为空 | 不重试，直接放弃 |

- 重试仍失败或确定性失败 → `summary_en` 置空，页面只显示标题（可接受降级）；同一条目跨批次不回补、不重复抓取；
- 优先处理最新条目（超出 20 条的老条目无摘要）。

## 5. 数据库设计（DDL，双方言）

**SQLite（主后端，`data/news.db`）**：

```sql
CREATE TABLE IF NOT EXISTS articles (
  id               INTEGER PRIMARY KEY AUTOINCREMENT,
  guid             TEXT NOT NULL UNIQUE,
  source           TEXT NOT NULL,
  category         TEXT NOT NULL,
  feed_topic       TEXT,
  title_en         TEXT NOT NULL,
  title_zh         TEXT,
  summary_en       TEXT,
  summary_zh       TEXT,
  url_display      TEXT NOT NULL,
  published_at     TEXT,          -- 新闻发布时间（RSS pubDate → ISO8601，Asia/Shanghai；缺失为 NULL）
  created_at       TEXT NOT NULL, -- 数据创建时间（首次抓取入库时间，ISO8601，Asia/Shanghai）
  translated       INTEGER NOT NULL DEFAULT 0,
  title_norm_hash  TEXT NOT NULL,
  is_important     INTEGER NOT NULL DEFAULT 0,
  important_reason TEXT
);
CREATE INDEX IF NOT EXISTS idx_dedup ON articles(source, title_norm_hash);
CREATE INDEX IF NOT EXISTS idx_day   ON articles(created_at);
CREATE INDEX IF NOT EXISTS idx_pub   ON articles(published_at);
CREATE INDEX IF NOT EXISTS idx_cat   ON articles(category, published_at);

CREATE TABLE IF NOT EXISTS fetch_batches (   -- 结构同需求文档 §6，sources_json 存 TEXT
  id INTEGER PRIMARY KEY AUTOINCREMENT, ran_at TEXT NOT NULL, duration_sec INTEGER NOT NULL,
  sources_json TEXT, items_new INTEGER DEFAULT 0, items_dup INTEGER DEFAULT 0,
  translate_ok INTEGER DEFAULT 0, translate_fail INTEGER DEFAULT 0, render_ok INTEGER DEFAULT 0
);

-- ===== 后期搜索预留（FR11）：FTS5 全文索引 + 自动同步触发器，零回填，本期不消费 =====
CREATE VIRTUAL TABLE IF NOT EXISTS articles_fts USING fts5(
  title_en, title_zh, summary_en, summary_zh,
  content='articles', content_rowid='id', tokenize='unicode61'
);
CREATE TRIGGER IF NOT EXISTS articles_fts_ai AFTER INSERT ON articles BEGIN
  INSERT INTO articles_fts(rowid, title_en, title_zh, summary_en, summary_zh)
  VALUES (new.id, new.title_en, new.title_zh, new.summary_en, new.summary_zh);
END;
CREATE TRIGGER IF NOT EXISTS articles_fts_ad AFTER DELETE ON articles BEGIN
  INSERT INTO articles_fts(articles_fts, rowid, title_en, title_zh, summary_en, summary_zh)
  VALUES ('delete', old.id, old.title_en, old.title_zh, old.summary_en, old.summary_zh);
END;
CREATE TRIGGER IF NOT EXISTS articles_fts_au AFTER UPDATE ON articles BEGIN
  INSERT INTO articles_fts(articles_fts, rowid, title_en, title_zh, summary_en, summary_zh)
  VALUES ('delete', old.id, old.title_en, old.title_zh, old.summary_en, old.summary_zh);
  INSERT INTO articles_fts(rowid, title_en, title_zh, summary_en, summary_zh)
  VALUES (new.id, new.title_en, new.title_zh, new.summary_en, new.summary_zh);
END;
```

**MySQL（可选后端，本地模式）**：同结构映射——`INTEGER/AUTOINCREMENT` → `BIGINT UNSIGNED/AUTO_INCREMENT`，`TEXT` 按长度映射 `VARCHAR/TEXT`，库 `market_dispatch`（utf8mb4）。由 db.py 方言层统一生成，业务代码只见同一套 CRUD 接口。FTS5 为 SQLite 专属；MySQL 后端的等价物是 `FULLTEXT` 索引，后期加搜索时按需创建，不影响本期。

guid 构成：bloomberg/wsj = 规范化真实 URL；reuters = `reuters:<title_norm_hash>`。

**扩展预留：全量搜索（本期不实施，需求 FR11）**——`articles` 的字段与索引已满足搜索/筛选/分页所需的全部查询维度（日期/分类/来源/要闻/中英标题摘要）；后期添加 = ① 新增月度 JSON 导出步骤（`data/months/YYYY-MM.json`）② 新增 `search.html` 客户端查询页（分词 AND / 分类 / 来源 / 日期范围 / 分页），均为纯增量，不改表、不迁移数据；本地/CLI 检索可直接使用 `articles_fts`（`WHERE articles_fts MATCH ?`，分词 AND 语义）。

## 7. HTML 日报设计与前后端渲染契约（v2 现代财经报刊风）

- **设计风格**：参考 FT / WSJ 现代财经报刊风——暖纸色底（`#F6F1E9`）、纯英文衬线报头 **Market Dispatch**（副标 `BLOOMBERG · REUTERS · WSJ`）、双线日期栏、高信息密度条目、克制色标，支持一键切换暗色模式（`localStorage` 键 `md_theme` 跨页同步）；
- **单文件自包含 + 轻量内联 JS**：CSS 与 JS 全部内联，零外部 CDN/字体请求，支持 `file://` 离线直接打开；
- **原子文件写入**：所有 HTML 输出均先写同目录临时文件再 `os.replace()` 原子替换，渲染异常绝不损坏既有页面；
- **可交互原型参考**：[docs/prototype/index.html](prototype/index.html)、[daily-2026-11-19.html](prototype/daily-2026-11-19.html)、[archive.html](prototype/archive.html)；

### 7.1 前后端模板数据契约（Backend `render.py` ↔ Frontend `templates/*.html.j2`）

| 模板 | 关键上下文变量 | 说明 |
|---|---|---|
| `daily.html.j2` | `page_date` / `weekday_cn` / `is_today` / `is_archived` | 当前版面日期、星期、是否为今日实时版、是否为已归档历史页 |
| `daily.html.j2` | `root_prefix` | 相对路径前缀：根 `index.html` 为 `""`，`daily/*.html` 与 `archive/*.html` 为 `"../"` |
| `daily.html.j2` | `recent_days` | 最近 3 天切换项列表（`date`, `short_label`, `count`, `href`, `is_active`, `is_today`） |
| `daily.html.j2` | `updated_at_hm` / `total_count` / `important_count` / `batches` | 最近更新时间、总条数、要闻数、当日批次健康列表（含单源失败标注） |
| `daily.html.j2` | `important_items` | 要闻头条区条目列表（按发布时间倒序，支持锚点 `#item-{{ id }}` 跳转及原文直链） |
| `daily.html.j2` | `sections` | 五大栏目有序列表（`key`, `icon`, `name`, `en_name`, `count`, `articles`）；栏内要闻置顶、其余按 `COALESCE(published_at, created_at)` 倒序 |
| `daily.html.j2` | `item` 字段 | `id`, `source`, `source_label`, `source_cls`, `is_important`, `important_reason`, `translated`, `title_zh`, `title_en`, `summary_zh`, `summary_en`, `url_display`, `pub_display`, `crt_display`, `is_cross_day` |
| `archive.html.j2` | `recent_days` / `months` / `total_archived_days` | 近 3 天切换项 + 按 `YYYY-MM` 倒序分组的归档日列表（含 5 栏计数、`important_count`、`total_count`、`href`） |

- **DOM / JS 交互属性约定**：
  - 栏目区块：`section.cat-sec[data-cat="markets|tech|world|us|china"]`
  - 条目节点：`article.item[id="item-{id}"][data-source="bloomberg|reuters|wsj"][data-star="0|1"]`
  - 来源色标：彭博 `#141414`（墨黑）、路透 `#C74F00`（深橙）、WSJ `#0A5894`（报刊蓝）；
  - 双时间格式：同日展示 `发布 14:26 · 抓取 15:02`，跨日自动带月日 `发布 11-19 23:42 · 抓取 11-20 00:05` 并展示「跨零点补入」提示；
  - 所有原文外链强制 `target="_blank" rel="noopener noreferrer"`；
  - 归天逻辑：`date(COALESCE(published_at, created_at))`（Asia/Shanghai）。

## 8. 调度与部署（云端主模式 + 本地可选）

### 8.1 云端主模式：GitHub Actions（双分支）+ SQLite + Pages

采用 **代码与产物分离的双分支架构**（`main` 存代码/模板/测试，`generated` 存 SQLite 数据库与静态站点，供 GitHub Pages 发布）：

- **CI 质量门禁（`.github/workflows/ci.yml`）**：每次 push / PR 到 `main` 自动安装依赖并运行 `pytest`，确保提交代码始终通过全量自动化测试；
- **每小时抓取发布流水线（`.github/workflows/news.yml`）**：
  - **触发**：`schedule: cron: '0 * * * *'`（每小时，UTC）+ `workflow_dispatch`（手动兜底）；
  - **步骤**：
    1. Checkout `main` 分支（获取最新代码与模板）；
    2. 拉取远端 `generated` 分支（首次运行自动初始化 orphan 分支）中的既有 `data/news.db`、`daily/`、`archive/` 到工作区；
    3. 安装 Python 3.12 + `requirements.txt`；
    4. 执行 `python -m src.main init-db` 与 `python -m src.main run`（可通过 GitHub Secrets 可选注入 `MD_LLM_API_KEY`）；
    5. 将最新 `data/news.db`、`index.html`、`daily/`、`archive/` 及 `.nojekyll` 同步至 `generated` 分支工作目录，使用中文 commit 信息提交（含 `[skip ci]`）并 push；
    6. GitHub Pages（源设为 `generated` 分支根目录）自动发布生效；
- **单一写入者**：仅 Actions 写 `generated` 分支与云端库；本地只读浏览或 `git pull`；
- **仓库活性**：每日自动提交即保持活跃，规避公开仓库 60 天无活动停用 schedule 的问题；
- 费用：公开仓库免费不限时；私有仓库 2000 分钟/月（本任务 ≤2 分钟/次 × 720 次/月 ≈ 1400 分钟，够用）。

### 8.2 本地可选模式（三平台）

| 平台 | 调度器 | 关键配置 | 部署 |
|---|---|---|---|
| macOS（开发机） | launchd | `RunAtLoad=true` + `StartInterval=3600` | `deploy/macos/*.plist` → `launchctl load` |
| Linux | systemd user timer | `OnBootSec=5min` + `OnUnitActiveSec=1h` + `Persistent=true` | `deploy/linux/*` → `systemctl --user enable --now` |
| Windows | 任务计划程序 | 每小时 +「错过后尽快运行」+ 登录时运行 | `deploy/windows/register-task.ps1`（schtasks） |

- 本地模式须避免与云端同时写同一数据：云端为主时本地仅浏览；确需本地运行则切独立 SQLite 文件或 MySQL；
- 调度输出统一重定向至 `logs/scheduler.out.log` / `scheduler.err.log`；
- **跨平台代码约束**：路径一律 `pathlib` 且相对项目根解析；时区用标准库 `zoneinfo`（Windows 自动回退 pip `tzdata`）；所有文件读写显式 `encoding="utf-8"`；统一入口 `run.sh` / `run.cmd`；不使用任何 macOS 专属 API。

## 9. 翻译模块

**Google 免费引擎（默认）**

```
GET https://translate.googleapis.com/translate_a/single?client=gtx&sl=en&tl=zh-CN&dt=t&q=<urlencoded>
```

- 标题、摘要分别请求；摘要截断至 1500 字符；
- 每条间隔 300ms 防限流；429/异常 → sleep 2s 重试 1 次 → 仍失败置 `translated=2`（保留英文）；
- 响应解析：`data[0][*][0]` 拼接。

**LLM 引擎（可选，config 一键切换）**

- OpenAI 兼容 `/chat/completions`；示例：智谱 `api_base: https://open.bigmodel.cn/api/paas/v4`，`model: glm-4-flash`（有免费额度，成本≈0）；
- 提示词：要求只输出 JSON `{"title_zh": "...", "summary_zh": "..."}`，财经术语准确（Fed→美联储等）；
- 标题+摘要合并为一次调用（省 token），失败降级逻辑同上；
- 运行环境：云端 runner（海外）访问 Google 接口稳定；本地模式若网络不可达则切 llm 引擎（智谱国内可达）。

## 10. 归档逻辑

- 每次运行末尾：`daily/` 中文件名日期 <（今天 − 2 天）→ `mv` 至 `archive/`（保留今天、昨天、前天共 3 天）；
- 随后重渲染 `archive/index.html`（按月分组）与根 `index.html`；
- 归档只移动文件，不删除任何数据（数据库全量 + HTML 全量永久保留）。

## 12. 风险与应对

| 风险 | 概率 | 应对 |
|---|---|---|
| Google News 限流/改版 | 中 | 失败退避 + 日志标注；备选方案：Reuters 官方 sitemap（实施时再验证） |
| 文章页 meta 抓取被拒（Akamai 等） | 高 | 摘要缺省为空只显示标题，不影响主流程（Bloomberg/WSJ 走 RSS 不受影响） |
| 免费翻译接口不稳定 | 中 | 重试 + 降级标注；config 一键切 LLM |
| Bloomberg/WSJ RSS 改版 | 低 | fetcher 适配器 + 配置化，改动局部化 |
| SQLite 损坏 / 仓库膨胀 | 低 | 每小时轻量提交 + 每月 VACUUM；git delta 压缩（预估年增长 20~40MB）；可从任意历史快照恢复 |
| Actions schedule 延迟 | 中 | 高峰期延迟数分钟~数十分钟；24h 回看 + 去重使延迟无实际影响；`workflow_dispatch` 手动兜底 |
| 国内访问 `*.github.io` 不稳 | 中 | 后置选项：Cloudflare Pages/CDN + 自定义域名托管，不动架构 |
| 跨天边界/时区混乱 | 低 | 全链路统一 Asia/Shanghai，「天」按 `COALESCE(published_at, created_at)` 决定，每小时重渲染近 3 天以覆盖跨零点晚到新闻 |
| 关键词分类不准 | 中 | 规则外置 config，试运行期根据结果调优 |
| 要闻漏标/误标（启发式判定） | 中 | 三信号互补降低漏标；阈值外置可调；标记只影响展示，不影响入库数据 |
| Windows 环境差异（时区库/编码） | 低 | pip `tzdata` 兜底；文件读写统一 UTF-8；日志不依赖控制台编码 |
