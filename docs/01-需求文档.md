## 1. 项目背景与目标

用户日常通过浏览器阅读 Bloomberg、Reuters、WSJ 三家媒体的财经资讯，希望有一个自动化工具：

- 定时抓取三家媒体**公开渠道**的新闻标题、摘要、链接（元数据）；
- 生成中英对照的本地 HTML 日报，按主题分栏浏览；
- 点击链接跳转浏览器阅读原文（阅读权限取决于用户自己的订阅状态）；
- 数据按天组织、自动去重、全量历史保留，支持日后回查。

## 2. 术语与合规边界

**术语**

- **条目（Item）**：一条新闻的元数据集合——标题、摘要、链接、发布时间、来源、主题分类。
- **批次（Batch）**：一次定时抓取运行。
- **日报（Daily Report）**：某一天的 HTML 聚合页面，当天滚动更新。

**合规边界（硬性约束，实现不得突破）**

1. 只采集**公开渠道的元数据**：RSS 中的标题/摘要/链接，以及页面对搜索引擎和社交分享公开的 `<meta name="description">` / `og:description` 标签；
2. **不抓取、不保存文章正文**；
3. **不绕过任何访问控制或付费墙**；
4. 对文章页面的 meta 请求限速（≤1 次/秒）；失败分类处理：瞬态错误（超时/5xx/429）重试 1 次，确定性错误（403/404/解析不到）不重试，直接放弃该条摘要；
5. 仅供个人学习，不对外分发内容。

## 3. 使用场景

1. 日常：浏览器打开 GitHub Pages 日报入口（任意设备），查看云端每小时更新的当日五栏要闻；
2. 点击任一条目标题，浏览器新标签页打开原文；
3. 周末/日后通过 `archive/` 回看历史日报（git 历史即全量存档）；
4. 可选：本地 `git pull` 保留离线副本，或以本地模式离线运行。

## 4. 功能需求

### FR1 数据源与频道

| 来源 | 接入方式 | 主题频道 |
|---|---|---|
| Bloomberg | 官方 RSS `www.bloomberg.com/feeds/{topic}/news.rss` | markets / economics / technology / politics |
| WSJ | 官方 RSS `feeds.content.dowjones.io/public/rss/*`（原 `feeds.a.dj.com` 实测已停更于 2025-01，改用新域名） | RSSMarketsMain / RSSWSJD（科技）/ RSSWorldNews |
| Reuters | Google News RSS `site:reuters.com when:24h`（2026-11-20 实测：reuters.com 直连 feed 全部 401，robots.txt 明示未经许可禁止自动化采集，故不走直连） | 不分频道，统一进入关键词分类器 |

- 三个来源的条目进入统一处理管道；
- 所有源 2026-11-20 实测可访问（见实施方案 §0）。

### FR2 抓取与调度

- **主模式（云端）**：GitHub Actions `schedule` cron 每小时 1 次，云端 24/7 运行，不受本机开关机影响；
- **可选模式（本地）**：开机时段每小时 1 次，登录/开机时立即运行一次（macOS launchd / Linux systemd timer / Windows 任务计划程序）；
- **回看窗口**：每次抓取均覆盖最近 24 小时（Google News 用 `when:24h`；RSS 全量拉取后按时间过滤）；
- **补抓机制**：错过时段（本地关机 / Actions 延迟）在下一次运行时由 24h 回看窗口天然补齐，配合去重不产生重复，无需独立回填任务；
- **时长约束**：单次运行（含翻译）≤ 2 分钟。

### FR3 去重

- **L1 URL 去重**（Bloomberg / WSJ）：解析并规范化 URL（去除 `utm_*`、`mod` 等跟踪参数，统一协议与域名大小写）作为唯一键 `guid`；
- **L2 标题哈希去重**（全部来源）：同来源、同一归属日（`date(COALESCE(published_at, created_at))`，Asia/Shanghai）内，标题规范化（小写、去标点、合并空白）MD5 哈希相同视为重复；
- **跨来源不合并**：同一事件不同媒体的报道各自保留（链接与视角不同）；
- 已入库条目不重复插入、不覆盖更新。

### FR4 主题分类

- 基于关键词规则（配置文件驱动，可自行增删关键词）分为五类：
  - `markets` 市场与经济（股市、宏观、央行、大宗商品）
  - `tech` 科技（AI、芯片、互联网公司）
  - `world` 政治与世界（地缘政治、政策、国际局势）
  - `us` 美国相关（美国国内政治/政策/政府/社会：Trump、White House、Congress、Supreme Court、Pentagon 等）
  - `china` 中国相关（China、Beijing、Xi、yuan、Taiwan 等）
- 初始类目由来源频道映射（如 Bloomberg technology → tech），Reuters 条目无频道信息，纯靠关键词判定；
- **覆盖优先级链**：`china` > `us` > 频道映射/关键词初始类目 > `world` 兜底；
- **栏目边界约定**：`us` 关键词只覆盖美国国内政治与政策；财经类词汇（Fed、Wall Street、美股）不进 `us` 栏、仍归 `markets`，避免掏空市场栏；美中双重命中（如关税战）按优先级归 `china` 栏；
- 未命中任何规则 → 兜底 `world`。

### FR5 翻译

- 默认引擎：Google 免费翻译接口（`translate.googleapis.com`，client=gtx），英→简体中文；
- 翻译对象：标题、摘要（无摘要则只译标题）；
- 失败处理：重试 1 次（间隔 2s）→ 仍失败则保留英文，页面标注「未翻译」；
- **LLM 开关**：配置中可将引擎切换为 `llm`（OpenAI 兼容协议，支持智谱 GLM 等），填入 `api_base / model / api_key` 即启用，翻译质量更好；
- 运行环境：Google 免费接口在云端 runner（海外）访问稳定；本地模式若网络不可达，切换 LLM 引擎（如智谱 glm-4-flash，国内可达）；
- 缓存：数据库中已有译文的条目不重复调用；
- 质量要求：财经术语准确（如 Fed → 美联储、Treasury yields → 美债收益率）。

### FR6 存储

- **存储抽象双后端**（config `storage.engine: sqlite | mysql`）：
  - **SQLite（主）**：`data/news.db`，标准库零依赖；云端模式随产物一起提交至 `generated` 数据分支持久化（git 即全量历史快照）；
  - **MySQL（可选）**：本地模式沿用（库 `market_dispatch`，utf8mb4）；
- 两张表（结构一致，仅方言差异）：`articles` 条目全量历史（只增不删）、`fetch_batches` 运行状态记录；
- **单一写入者原则**：同一数据库同一时间只有一方写入（云端 Actions 或本地运行，二选一）；
- **HTML 文件**：
  - `daily/YYYY-MM-DD.html`：每日日报，保留**最近 3 天**（含当天）于 `daily/`；因按 `published_at` 归天，每次运行重渲染近 3 天日报以覆盖跨零点补抓；
  - 根目录 `index.html` **直接呈现今日日报内容**（与当日 `daily/YYYY-MM-DD.html` 同模板，顶部提供近 3 天切换与归档入口）；
  - 超过 3 天的日报文件移入统一归档文件夹 `archive/`，文件保留不删除；`archive/index.html` 为历史归档索引；
  - 云端模式下以上产物随 `generated` 分支提交，并通过 GitHub Pages 发布。

### FR7 日报渲染

- **自包含单文件 HTML + 轻量内联 JS**：内联 CSS + 内联 JS，无外部 CDN/字体依赖，离线双击可开、交互完整；
- **视觉风格**：现代财经报刊风（类似 FT / WSJ），暖纸底色、清晰衬线/无衬线标题层级、高信息密度，支持一键切换暗色模式（夜间版）；
- **报头与导航**：
  - 报头：标题、版面日期与星期、最近更新时间、当日总数、当日批次健康状态（可点击展开查看各批次详情与失败源）；
  - **近 3 天切换条**：顶部一键切换「今天 / 昨天 / 前天」及右侧「历史归档 →」；
  - **阅读控制条**：栏目筛选（全部 + 五栏计数）、来源筛选（彭博 / 路透 / WSJ）、⭐ 仅看要闻开关、双语 / 仅中文切换、批量展开/收起英文原摘要；
- **今日要闻头条区**（FR10）：报头下方集中展示当日 ⭐ 要闻（支持快速定位到所属栏目或直接打开原文）；
- **五个主题分栏**（支持全部展示或按栏目聚焦）：
  - 📈 市场与经济　💻 科技　🌍 政治与世界　🇺🇸 美国相关　🇨🇳 中国相关
- **条目字段**（栏内 ⭐ 要闻置顶，其余按 `published_at` 倒序）：
  - 来源徽章（彭博 / 路透 / WSJ）+ **明确双时间**（`发布 HH:MM · 抓取 HH:MM`，跨天自动带日期如 `发布 11-19 23:45 · 抓取 11-20 00:08`）；
  - 要闻条目：⭐ 徽章 +「要闻」标签 + 命中原因 + 左侧强调色条；
  - 中文标题 + 英文原标题（均可点击，`target="_blank" rel="noopener"` 新标签页打开原文；切「仅中文」时隐藏英文原标题，未翻译条目除外）；
  - 中文摘要（无摘要时平滑省略不占位）；
  - 英文原摘要默认折叠，支持单条展开或工具栏批量展开；
- 未翻译条目显示英文原标题并标注「未翻译」；
- 页脚：运行状态说明与归档链接。

### FR8 索引与归档

- 根 `index.html`：直接展示今日日报，顶部切换条串联最近 3 天（`index.html` / `daily/昨天.html` / `daily/前天.html`）与 `archive/index.html`，每次运行后刷新；
- `archive/index.html`：历史日报列表（按年/月分组，展示各栏条数、要闻数、总数），归档动作发生时刷新。

### FR9 运行状态与日志

- 每次运行写日志 `logs/YYYY-MM-DD.log`：各源抓取条数、新增/去重数、翻译成功/失败数、耗时、异常堆栈；
- 存储异常或渲染失败时：记录日志、保留上一次的 HTML 不动，等待下一小时重试；云端模式下 Actions 运行记录本身即运行日志备份。

### FR10 重要新闻标记（要闻）

RSS 元数据中不存在「头版头条」官方字段，采用**三信号自动打分**启发式判定（规则与阈值全部配置化）：

| 信号 | 规则 | 分值 |
|---|---|---|
| 标题特征词 | 标题匹配 `breaking / exclusive / urgent` 等特征词（不区分大小写） | +2 |
| 跨源同事件 | 当日与**另一来源**条目的标题词集 Jaccard 相似度 ≥ 0.55 | +2 |
| GN 头条命中 | 与 Google News「Top Stories / Business」话题源中**同一媒体**的头条标题模糊匹配（Jaccard ≥ 0.5） | +3 |

- 总分 ≥ 2 → 标记 `is_important = 1`，同时记录命中原因（`标题特征词` / `跨源报道` / `GN头条`，多信号以 ` · ` 或逗号分隔叠加）；
- **近 3 天受影响日期重算**：跨源信号依赖后到的报道，且跨零点新闻按 `published_at` 归属昨日，每次批次入库后对**发生变更的近 3 天日期**内全部条目重算重要性并回填（只影响标记，不影响入库与去重）；
- 与 FR3「跨来源不合并」不冲突：仅互相标记关联，条目仍各自独立保留；
- 判定为启发式，允许个别漏标/误标，试运行期根据效果调阈值；
- 展示形式见 FR7：⭐ 置顶 + 强调样式 + 页首要闻速览框。

### FR11 全量搜索（本期不实施，预留设计）

本期专注云端部署落地，搜索功能后期以**纯增量**方式添加——不修改现有表结构、不迁移已有数据、不影响当日日报与 3 天索引/归档结构：

- **数据层（本期就位）**：
  - `articles` 已具备搜索所需全部查询维度：`created_at` / `published_at`（日期范围）、`category`（分类筛选）、`source`（来源筛选）、`is_important`（仅看要闻）、中英标题与摘要（匹配目标），且 `idx_day / idx_cat / idx_dedup` 索引已覆盖；
  - `init-db` 时同步创建 FTS5 全文索引虚拟表 `articles_fts`（覆盖 title_en / title_zh / summary_en / summary_zh）及 INSERT/UPDATE/DELETE 同步触发器，随日常写入自动维护、零回填——后期本地/CLI 检索即开即用；
- **站点层（后期添加）**：新增按月数据导出 `data/months/YYYY-MM.json` 渲染步骤 + 全量查询页 `search.html`：关键词分词 AND 匹配标题（中英）、分类/来源筛选、日期范围、分页（默认每页 20 条、默认最近 30 天），客户端 JS 查询，兼容 GitHub Pages 静态托管；
- 本期采用 v2.0「首页即今日日报 + 顶部近 3 天切换 + 历史归档」结构，搜索页作为纯增量扩展留待后期。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 单次运行 ≤ 2 分钟；单条翻译 ≤ 3s；对文章页 meta 请求限速 ≤1 次/秒 |
| 可靠性 | 单源失败不影响其他源；外部接口失败有降级路径；程序异常不影响已有 HTML |
| 可维护性 | 数据源、关键词、翻译引擎、路径全部配置化（config.yaml）；新增来源只需一个 fetcher 模块 + 配置 |
| 时区 | 统一使用 `Asia/Shanghai` 定义「天」；`published_at` 与 `created_at` 均存为 `Asia/Shanghai` ISO-8601（`YYYY-MM-DDTHH:MM:SS+08:00`） |
| 环境 | 云端主环境：GitHub Actions（Linux runner）+ GitHub Pages；代码跨平台（macOS/Linux/Windows 可本地运行）；Python 3.10+（开发机 3.14）；SQLite 标准库（可选 MySQL 5.7+） |

## 6. 数据字典

### articles 表

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT UNSIGNED PK AI | 自增主键 |
| guid | VARCHAR(191) UNIQUE | 唯一键：bbg/wsj = 规范化真实 URL；reuters = `reuters:` + 标题哈希 |
| source | VARCHAR(16) | bloomberg / reuters / wsj |
| category | VARCHAR(16) | markets / tech / world / us / china |
| feed_topic | VARCHAR(32) | 抓取频道（markets/economics/technology/politics 等，reuters 为空） |
| title_en | VARCHAR(512) | 英文标题 |
| title_zh | VARCHAR(512) | 中文标题（未译为 NULL） |
| summary_en | TEXT | 英文摘要 |
| summary_zh | TEXT | 中文摘要（未译为 NULL） |
| url_display | VARCHAR(1024) | 点击用链接（原文 URL 或 Google News 跳转链接） |
| published_at | DATETIME | 新闻发布时间（取自 RSS `<pubDate>`，转为 Asia/Shanghai；缺失为 NULL） |
| created_at | DATETIME | 数据创建时间（首次抓取入库时间，Asia/Shanghai，NOT NULL） |
| translated | TINYINT | 0 未译 / 1 已译 / 2 翻译失败 |
| title_norm_hash | CHAR(32) | 规范化标题 MD5（L2 去重） |
| is_important | TINYINT | 0 普通 / 1 要闻（三信号打分 ≥ 2，批次后对受影响的近 3 天日期重算） |
| important_reason | VARCHAR(128) | 命中信号（`标题特征词` / `跨源报道` / `GN头条`，多信号以 ` · ` 分隔） |

索引：`(source, title_norm_hash)` L2 去重查询、`(created_at)` 入库时间查询、`(published_at)` 发布时间与归天查询、`(category, published_at)` 栏内排序。另建 `articles_fts`（FTS5 虚拟表）与同步触发器，随 articles 自动维护，为后期搜索预留（本期不消费，见 FR11）。

## 7. 验收标准

1. 连续运行 2 天：日报按时滚动更新，重复抓取产生 0 条重复条目；
2. 三来源均有产出（Reuters 依赖 Google News，允许个别小时为空）；
3. 翻译成功率 ≥ 90%，失败条目明确标注「未翻译」；
4. 任意条目点击后在浏览器正确打开原文页面；
5. 第 4 天验证：`daily/` 仅保留 3 个文件，`archive/` 出现归档文件且索引可达；
6. 断网 / 单源失败 / 存储异常时程序不崩溃，日志可诊断，已有 HTML 不受损；
7. 要闻标记：三信号均可触发，⭐ 条目置顶且样式区分明显，速览框锚点跳转正常；
8. 云端主模式：Actions 每小时产出并提交 generated 分支，GitHub Pages 可正常访问当天日报与索引。

## 8. 明确不做的事

- 不抓取、不保存文章正文，不做全文存档；
- 不绕过任何付费墙或访问控制；
- 不做跨来源事件合并/聚类（仅按主题分栏）；
- 不做对外发布、分享、推送功能；
- 不做正文内容的中英对照（只翻译标题与摘要元数据）；
- 本期不做全量搜索页（数据库已预留 FTS5 扩展，后期增量添加，见 FR11）。
