## 1. 本地开发与验证（macOS / Linux / Windows）

### 1.1 初始化虚拟环境与依赖

```bash
# macOS（推荐 Homebrew Python 3.10+，如 /opt/homebrew/bin/python3）
/opt/homebrew/bin/python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt
```

Windows PowerShell：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt -r requirements-dev.txt tzdata
```

### 1.2 准备配置文件

```bash
cp config/config.example.yaml config/config.yaml
```

- 默认配置即使用 `SQLite`（`data/news.db`）+ `Google gtx` 免费翻译，无需任何密钥即可直接运行。
- 如需切换 LLM 翻译引擎，修改 `config/config.yaml` 中 `translator.engine: llm` 并填写 `api_base` / `model`，密钥推荐通过环境变量注入：
  ```bash
  export MD_LLM_API_KEY="你的API密钥"
  ```

### 1.3 常用 CLI 命令

| 命令 | 用途 |
|---|---|
| `python -m src.main init-db` | 初始化数据库表、索引与 SQLite FTS5 全文索引及触发器（幂等可重入） |
| `python -m src.main run` | 执行完整流程：并行抓取 → 分类 → 去重 → meta 回退 → 翻译 → 要闻重算 → 归档 → 渲染 |
| `python -m src.main run --no-translate` | 仅抓取与渲染（跳过翻译，调试抓取用） |
| `python -m src.main render` | 不抓新数据，仅从数据库重新渲染近 3 天页面、根 `index.html` 与 `archive/index.html` |
| `python -m src.main archive` | 手动触发一次 3 天归档与归档索引刷新 |
| `python -m src.main status` | 查看数据库总量、近 3 天条数、最近批次运行状态与各源健康度 |
| `python -m src.main vacuum` | 执行 SQLite `VACUUM` 压缩数据库体积（建议每月执行一次） |

## 2. 云端主模式部署（GitHub Actions + GitHub Pages）

### 2.1 分支架构

- `main` 分支：存放源代码、模板、测试、工作流配置与文档。
- `generated` 分支：由 `.github/workflows/news.yml` 自动维护，仅保存 `data/news.db`、`index.html`、`daily/`、`archive/` 与 `.nojekyll`，作为 GitHub Pages 发布源。

### 2.2 一次性开通步骤

1. 将本地仓库推送到 GitHub 的 `main` 分支（确保仓库开启 **Actions** 权限，并在 `Settings → Actions → General → Workflow permissions` 勾选 **Read and write permissions**）。
2. （可选）如使用 LLM 翻译引擎，在 `Settings → Secrets and variables → Actions` 新增 Secret `MD_LLM_API_KEY`，并在 `config/config.example.yaml`（或工作流环境变量）启用 `MD_TRANSLATOR_ENGINE=llm`。
3. 在 GitHub 仓库 `Actions` 页面手动触发一次 **Market Dispatch 定时抓取与发布**（`workflow_dispatch`），流水线将自动创建 `generated` 分支并推送首批数据与页面。
4. 进入 `Settings → Pages`，将 **Build and deployment → Source** 设为 `Deploy from a branch`，分支选择 `generated`，目录选择 `/ (root)`，保存后约 1 分钟即可通过 `https://<用户名>.github.io/<仓库名>/` 访问。

### 2.3 CI 质量门禁

- `.github/workflows/ci.yml` 会在每次推送或提交 PR 到 `main` 时自动执行全量 `pytest`，保障主干代码质量。

## 3. 本地可选定时部署（三平台）

> 注意遵守**单一写入者原则**：已启用云端 Actions 时，本地仅需浏览或 `git pull`；如切换为本地离线运行，请停用云端 schedule 或使用独立数据库文件。

### 3.1 macOS（launchd）

1. 编辑 `deploy/macos/com.personal.market-dispatch.plist` 中的项目绝对路径；
2. 复制到 `~/Library/LaunchAgents/` 并加载：
   ```bash
   cp deploy/macos/com.personal.market-dispatch.plist ~/Library/LaunchAgents/
   launchctl load -w ~/Library/LaunchAgents/com.personal.market-dispatch.plist
   ```
3. 停用：`launchctl unload -w ~/Library/LaunchAgents/com.personal.market-dispatch.plist`

### 3.2 Linux（systemd user timer）

1. 按实际路径修改 `deploy/linux/market-dispatch.service`；
2. 安装并启用：
   ```bash
   mkdir -p ~/.config/systemd/user
   cp deploy/linux/market-dispatch.{service,timer} ~/.config/systemd/user/
   systemctl --user daemon-reload
   systemctl --user enable --now market-dispatch.timer
   ```

### 3.3 Windows（任务计划程序）

以当前用户运行 PowerShell 脚本注册每小时任务与登录自启：

```powershell
powershell -ExecutionPolicy Bypass -File .\deploy\windows\register-task.ps1
```

## 4. 日常运维与故障排查

| 现象 | 排查方式 | 处理建议 |
|---|---|---|
| 某批次 Reuters 失败 | 查看 `logs/YYYY-MM-DD.log` 或页头批次抽屉 | Google News 偶发 429/超时属正常现象，下小时 24h 回看自动补齐 |
| 大量条目显示「未翻译」 | 检查网络能否访问 `translate.googleapis.com` | 本地国内网络建议切 `translator.engine: llm`（如智谱 `glm-4-flash`） |
| 归档后需要补查旧新闻 | 打开 `archive/index.html` 或对 `data/news.db` 用 SQLite FTS5 查询 | `sqlite3 data/news.db "SELECT id, title_zh FROM articles WHERE id IN (SELECT rowid FROM articles_fts WHERE articles_fts MATCH '美联储');"` |
| 数据库文件体积增长 | 查看 `ls -lh data/news.db` | 运行 `python -m src.main vacuum` 释放空闲页 |
| HTML 样式改动需刷新历史页 | 修改 `templates/daily.html.j2` 后 | 运行 `python -m src.main render` 一键重渲染近 3 天与索引 |
